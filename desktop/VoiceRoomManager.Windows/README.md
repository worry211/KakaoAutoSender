# VoiceRoom Manager Windows v0.4.0 RC4

독립 Windows x64 유틸리티입니다. 실제 Kakao에서 생성, 전용 창 활성 확인, 마이크·스피커 자동 음소거를 확인했습니다. **48시간 운영과 모든 판매 승인 게이트를 통과한 정식판은 아닙니다.** Android v0.5.1과 backend 소스는 이번 Windows 변경에서 유지했습니다. Kakao 공식 제품이 아닙니다.

## 시작하기

1. 공식 KakaoTalk에 로그인하고 이미 참여한 OpenChat의 정확한 이름과 `https://open.kakao.com/o/...` 링크를 등록합니다.
2. `전체 시작`을 누릅니다. 신규 미검증 방도 순서대로 처리합니다.
3. 활성·보호 상태, 남은 시간, 다음 점검, 최근 성공을 확인합니다. 시작시각 불명인 기존 방에 임의로 48시간을 부여하지 않습니다.
4. 사용자 조치 안내를 해결한 후 선택 방을 재확인합니다. `전체 중단`은 자동 입력/재시도를 취소하고 실제 보이스룸은 유지합니다.

Windows 10 2004 이상 / Windows 11 x64, 공식 KakaoTalk 로그인과 OpenChat 참여 권한이 필요합니다. self-contained EXE이므로 별도 .NET 설치가 필요 없습니다. 한국어 OCR에는 Windows 한국어 인식 언어가 필요합니다. 화면 인식은 로컬에서 처리하며 서버에 업로드하지 않습니다.

## RC4 기능과 구조

- `RoomWorkflow` 한 경로가 설정 → Kakao 실행 → browser landing/preview → 정확한 채팅 → 기존 활성/생성 → 오디오 검증을 소유합니다. 방 진입 후 다른 검색으로 성공을 취소하거나 `RICHEDIT`를 다시 요구하지 않습니다.
- 작업마다 room ID, 공식 링크, Kakao PID, 검증 창, 취소와 제한 시간을 묶습니다. 재시작 때 저장된 활성·음소거 증거를 폐기하고 실제 화면부터 확인합니다.
- UIA가 비어 있는 전용 `보이스룸: 방 이름` 창도 같은 PID, 정확한 제목, 참여 인원, 다섯 개 오디오/퇴장 컨트롤의 형태를 함께 확인합니다. 활성과 음소거는 반복 관찰하며 창 존재만으로 성공하지 않습니다.
- 마이크·스피커의 실제 ON/OFF glyph를 구별합니다. 확인된 ON만 음소거하고 OFF를 다시 읽습니다. 알 수 없는 상태를 임의로 토글하거나 전역 Windows 음량을 바꾸지 않습니다. 전환 애니메이션에는 입력을 반복하지 않고 최대 네 번 읽기만 재시도합니다.
- 기본 메뉴는 정확한 채팅 헤더의 검색/보이스룸/전화/메뉴 네 아이콘을 함께 검증합니다. 채팅 메시지의 ‘보이스룸’ 글자를 메뉴로 클릭하지 않습니다. 선택적 호환성 지점은 고급 진단에 있습니다.
- 생성 폼 제목·기본 이름 안내·제출 컨트롤을 확인합니다. 제출 직전에 `CreationUncertain`을 저장하여 중단/재시작/검증 실패 후 중복 생성을 막습니다.
- 명시적 종료 안내 세 문구를 두 번 읽고 종료 창이 실제 닫혔을 때 재생성을 허용합니다. 일시적으로 창이 사라지면 재점검하며 생성 불확실성을 유지합니다.
- 실행 중 5초 tick과 주기 건강점검으로 상태를 다시 확인합니다. 다른 앱이 전경이면 runtime 입력을 건너뛰며 주기 점검에서 실제 상태를 확인합니다. 사용자 조치 상태에서 자동 입력을 반복하지 않습니다.
- 명시적 요청 거절/요청받기 차단 컨트롤만 처리하고 결과를 재확인합니다. 빈 UIA 전용 창에서 모든 요청 처리가 가능하다고 주장하지 않습니다. 다른 계정의 실제 요청 시험은 남았습니다.
- 전체 다시 점검, 선택 방 확인, 방 설정 백업·복원, 작업 소요 시간/OS/Kakao 진단, 회전 로그, 최근 실패와 재보호 횟수를 제공합니다. 설정 복원에 활성 증거·생성시각·불확실성을 가져오지 않습니다.
- 다크 대시보드, 남은 시간, 다음 점검, 최신 버전 표시와 고급 진단 분리. 재표시 때 선택 방을 유지하고 OCR 엔진을 직렬화·재사용하며 중복 UIA 읽기와 고정 대기를 줄였습니다.

## 운영과 복구

UI 작업은 단일 실행이고 다중 방은 순차 처리합니다. 오류를 격리하고 약 10초 → 30초 → 90초 → 274초 → 최대 10분 backoff를 사용합니다. 확정할 수 없는 보호/호환성에는 사용자 조치를 안내합니다. 실제 생성 증거가 있을 때만 시작시각을 기록합니다. 최대 5분 건강점검, 47시간 55분 사전점검과 만료 전후 1분 점검이 있으며 타이머 자체는 생성 명령이 아닙니다.

모니터 OFF 운영, Windows 잠금 시 입력 대기, 정상 해제 후 재개, Kakao/앱 재시작 복구와 Windows 로그인 자동실행을 구현했습니다. 물리 모니터 OFF·잠금/Windows 재시작의 종합 실기 시험은 별도 승인 게이트입니다. 한 세션에서 앱 중복 실행을 차단합니다.

`%LOCALAPPDATA%/VoiceRoomManagerWindows/`에 설정/백업/호환성 지점과 회전 로그를 저장합니다. 손상 원본을 보존하며 백업 복구 시 자동관리는 OFF로 시작합니다. 지원하지 않는 schema, 중복 ID, 과도한 파일 크기는 거절합니다. 진단 ZIP에는 방 이름/링크가 들어갈 수 있으므로 공유 전에 확인하세요.

## 검증과 한계

Windows 테스트 **121개 통과**: 상태 머신, 수명, 오류 격리, 재시작/생성 불확실성, 손상된 설정, 안전한 설정 가져오기, OCR 동시성, 실제 컨트롤 fixture와 잘못된 glyph 거절, 100/150/200% 검출. fixture 배율 검증을 실제 다중 모니터 시험으로 간주하지 않습니다.

2026-10-05 대상 PC / Kakao 26.8.1.5315의 실제 관찰:

- RC3 전체 시작으로 browser → preview → 정확한 방 `1` → 실제 생성(10:46 KST).
- RC4 개발 중 명시적 종료 창 자동 확인/닫기 → 실제 재생성(11:27).
- 신규 생성(11:58)은 당시 메뉴 호환성 지점을 사용했습니다. 최종 기본 네 아이콘 메뉴는 실제 안전 진단에서 캘리브레이션 없이 인식됐습니다(12:18).
- 실행 중 스피커 ON → 자동 OFF와 ACTIVE/두 음소거 유지 및 재보호 횟수 증가(12:27). 시험 포인터 강조를 컨트롤에서 옮긴 뒤 확인했습니다.
- 재시작 후 실제 마이크 ON·스피커 ON을 자동 OFF로 전환하고 두 번 확인(12:00). 보호된 기존 방 점검은 약 2.2초(12:05), 약 1.8초(12:18). 해당 PC/화면의 관찰이며 전체 생성 시간 보장이 아닙니다.

최종 바이너리에서 캘리브레이션 없이 신규 생성부터 보호까지 이어지는 종합 run, 다른 계정 요청, 계정별 다중 방 한도, 물리 모니터 OFF/잠금/Windows 재시작, 실제 48시간 만료는 남았습니다. UIA/OCR/glyph/정확한 제목을 확정할 수 없는 버전에서는 대기합니다. native UIA provider가 멈추면 90초 cooperative 제한을 넘길 수 있습니다. CAPTCHA, 보안인증, 잠금, 계정/플랫폼 제한 우회는 구현하지 않습니다. EXE는 unsigned RC입니다.

## 빌드

```powershell
dotnet test desktop/VoiceRoomManager.Windows.Tests -c Release
./scripts/package-voiceroom-windows.ps1 -OutputDirectory ./out/windows
```

CI는 Release build, 테스트, self-contained EXE, ZIP, SHA-256과 결과 artifact 업로드를 실행합니다. 기존 Android/backend CI도 유지합니다.
