# 사진 예약·반복 시험판 2.3.8 (39)

## 확인된 사실과 이번 변경

사용자는 2.3.7 사진 키보드로 오픈채팅 사진 전송에 성공했다고 보고했다. 추가 확인에서 **카카오톡의 마지막 전송 버튼을 사람이 한 번 더 눌렀다**고 답했다. 따라서 키보드 입력 수락만으로 자동 전송 완료를 판단할 수 없다.

2.3.8은 현재 확인한 하나의 채팅방에 한정한 예약 엔진과, 사람이 실제로 누른 사진 전송 버튼을 학습하는 접근성 보조를 추가한다. 이 새 예약·최종 클릭·복귀 흐름은 코드와 모형 테스트를 완료한 시험 기능이며 실제 기기 동작은 미검증이다. 다른 방 자동 선택, 여러 방 순회, 카카오톡 재실행 후 자동 연결은 구현하지 않았다.

## 사용 절차

1. 기존 앱을 지우지 말고 같은 서명 APK를 덮어설치한다. 시험용 방과 사진을 사용한다.
2. 방 설정에서 반복 간격 또는 매일 지정 시각과 하루 최대 요청 횟수를 저장한다. 이 방의 기존 알림 자동전송은 끈다. 다른 방의 문자 예약은 유지할 수 있다.
3. 사진 키보드 설정에서 사진 키보드와 ‘카톡매크로 사진 전송 보조’ 접근성을 켠다. 정확한 예약 권한, 중지 알림 권한도 설정할 수 있다. 접근성은 방 제목·화면 구조를 기기 안에서 확인하고 학습한 사진 전송 버튼만 누른다. 대화/입력 문구를 저장하거나 서버로 보내지 않는다.
4. 카카오톡의 시험 방을 직접 열고 메시지 입력창에서 사진 키보드를 선택한다. 입력 중인 문구는 먼저 정리한다.
5. 사진을 고르고 현재 받는 방 확인을 체크한다. ‘자동 전송 준비 · 전송 버튼 학습 (1회)’을 누른다. 카카오톡 사진 화면에서 마지막 전송 버튼을 직접 한 번 누른다. **학습도 실제 사진 한 장을 전송한다.**
6. 원래 채팅방으로 돌아온 뒤 입력창을 눌러 사진 키보드를 열고 사진을 다시 고른다. 학습 완료 안내를 확인하고 현재 방 확인을 체크한다.
7. ‘다음 일정에 1회 예약’ 또는 ‘저장한 일정으로 반복 시작’을 누른다. 일정은 저장한 방 설정에서 가져온다. 문구는 함께 보내지 않는다. 사진 출처의 방 이름으로 수신자를 추측하지 않는다.
8. 기본 모드에서는 같은 채팅방과 키보드를 유지한다. 다른 앱·방으로 이동하거나 키보드 연결이 끝나면 예약을 중지한다. 재부팅·업데이트·프로세스 종료 후에는 현재 방을 확인하고 다시 시작해야 한다.
9. 키보드의 ‘사진 예약 즉시 중지’, 예약 알림의 중지, 앱의 전체 중지, 사진 키보드 설정의 중지 중 하나로 중단한다.

## 화면 꺼짐 시도

사진 미리보기에서 ‘화면 꺼짐에서도 시도 · 실험 기능’을 별도로 선택할 수 있다. 기본값은 꺼짐이다.

이 옵션은 **Android가 같은 카카오톡 입력 연결과 학습 화면 접근을 계속 허용하는 경우에만** 화면을 켜지 않고 기존 경로를 시도한다. 임의의 과거 연결을 보관해 재연결하지 않는다. 입력 연결 종료, 잠금 화면으로 대상 변경, 사진 화면 확인 불가 또는 최종 버튼 실행 거절이면 중지한다. 화면 켜기, 잠금 해제, 잠금 우회 코드는 없다. 화면 꺼짐 상태의 실제 전송 성공은 아직 확인하지 않았다. 일반 휴대폰에서 항상 되는 완성 기능이라고 판매할 수 없다.

짧은 부분 깨우기 잠금은 사진 파일 확인 및 최종 절차 동안 CPU만 유지하고 화면은 켜지 않는다. 알람과 접근성·키보드 서비스를 사용하는 것으로 Android의 입력/잠금 제한을 없애지는 못한다. 절전 중에는 알람이 늦어질 수 있다. 정확한 알람 권한이 없어도 근사 알람으로 예약하되 상태 화면에 이를 표시한다.

## 잘못된 전송과 중복 방지

- 학습과 매 예약 시작에 현재 카카오톡 채팅창을 확인한다. 연결은 창 ID, 유일한 메시지 입력창 ID, 상단 방 제목의 해시로 묶는다. 같은 이름의 다른 창은 같은 방으로 취급하지 않는다.
- 사진 전송 화면은 사람이 누른 버튼의 화면 클래스, 전체 자원 ID/클래스 구조, 버튼 ID/클래스/문구가 일치하고 전송 후보가 유일할 때만 처리한다. 좌표, OCR, 유사 문구로 버튼을 추측하지 않는다. 정보가 노출되지 않는 카카오톡 화면은 지원하지 않는다.
- 전송 직전에 활성 창·버튼·구조를 다시 확인하고, 자동 실행 중 다른 조작이 감지되면 중지한다. 같은 사진 화면의 버튼은 한 번만 실행한다.
- 다음 반복은 최종 버튼 실행 뒤 원래 창·제목·입력창으로 돌아오고 새로운 사진 입력 연결이 확인됐을 때만 예약한다. 늦은 예약을 연속으로 몰아서 전송하지 않는다.
- 알람의 실행 ID와 예정 시각을 검사한다. 사진 요청 전 저장소에 실행을 소비하고 시도 횟수를 동기 기록한다. 중복 알람·프로세스 종료·불명확 응답이 같은 실행을 재생하지 못한다.
- 거절, 사진 읽기 실패, 8초 파일 처리 제한, 15초 사진 화면/복귀 제한, 설정 변경, 접근성 해제, 라이선스 만료·서버 확인 실패는 중지로 처리한다. 재시도를 통해 중복 사진을 만들지 않는다.
- 하루 한도는 **수신 성공이 아닌 사진 요청 시도 횟수**를 제한한다. 불명확 응답도 횟수에 포함하고 재시작해도 초기화하지 않는다. 한도 도달 뒤 반복은 다음 날로 넘긴다. 이전 날짜의 횟수 키는 정리한다.
- 같은 방의 기존 알림 예약과 키보드 예약을 동시에 실행하지 않는다. 문자 예약 동작은 유지한다. 키보드 예약은 기존 알림 전송 성공 횟수를 늘리지 않는다.
- ‘입력 수락’, ‘전송 버튼 실행’, ‘원래 방 복귀’는 서버/상대방의 사진 수신 확인이 아니다. 앱은 실제 도착을 검증했다고 표시하지 않는다.
- 휴대폰 시간·시간대가 바뀌면 예약을 중지한다. 라이선스 서버 확인은 기존 정책에 따라 주기적으로 수행하고 최종 클릭 직전에도 유효성을 검사한다.

## 실제 기기 검증 순서

1. 기존 데이터 유지와 기존 수동 사진·문자 예약 확인.
2. 접근성 연결 후 실제 시험 방에서 학습용 1회 전송. ‘학습 완료’가 안 나오면 자동 예약을 진행하지 않는다.
3. 화면 ON으로 다음 일정 1회 예약. 손을 대지 않고 최종 버튼 실행 및 원래 방 복귀, 실제 사진 도착을 확인한다.
4. 화면 ON으로 1분 간격 3회/한도 3회 시험. 중복·잘못된 방 전송·한도 초과가 없어야 한다.
5. 정상 동작을 확인한 뒤 별도로 화면 꺼짐 시도를 켜고 한 번만 예약한다. 화면을 끄고 수신 기기에서 확인한다. 실패/중단이면 지원하지 않는 상태로 기록한다.
6. 잠금, 다른 방 전환, 같은 이름의 방, 전송 화면의 다른 조작, 사진 제거, 일정 변경, 전체 중지, 접근성 해제, 라이선스 정지, 앱 강제 종료, 재부팅, 시각 변경을 각각 시험한다.
7. 요청 수락만으로 수신 성공을 표시하지 않고, 알림 중지로 후속 클릭과 예약이 모두 취소되는지 확인한다.

실기기 검증 전에는 판매 지원표나 자동 업데이트에 예약 사진·화면 OFF 지원을 확정하지 않는다.

## 플랫폼 근거

- [Android Image keyboard support](https://developer.android.com/develop/ui/views/touch-and-input/image-keyboard): 수신 앱도 참여해야 하며 `commitContent` 수락이 비동기 로딩·실제 수신 완료를 보장하지 않는다.
- [InputMethodService](https://developer.android.com/reference/android/inputmethodservice/InputMethodService): 입력 대상 변경과 입력 종료 수명주기.
- [Schedule alarms](https://developer.android.com/develop/background-work/services/alarms): 정확한 알람 권한과 절전 중 실행 지연.

이전 버전의 문서는 해당 버전의 범위를 설명한다. 현재 예약 구현 범위는 이 문서를 따른다.
