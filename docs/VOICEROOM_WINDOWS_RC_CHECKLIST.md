## RC12 활성 판별 및 스피커 요청 차단 수정 — 2026-10-18

사용자 첨부 화면과 운영 로그에서 `circles=5`지만 `glyphs=0.000,1.000,0.007`로 손 아이콘만 불일치해 전체 footer를 버리는 문제를 재현했다. 요청 비활성화 시 손 아이콘은 밝은 원 안의 검은 손+X로 바뀐다. 이 상태를 별도 RequestState.Blocked로 인식하며, 요청 아이콘이 미지원이면 음소거 증거와 분리해 요청 차단 미확인으로 표시한다. 마이크/스피커/heart/exit/참여자/방/PID 증거는 계속 검증한다.

긴 방 제목은 두 줄로 표시되어 참여 인원 줄이 기존 y58–90 인식 범위 아래에 있었다. y48–112 범위로 조정하고 배율/이동 후 새 bounds를 반영한다. 정확한 native 방 이름과 PID 확인은 유지한다. UIA 비어 있음만으로 생성 실패라고 추정하지 않는다.

요청 허용 상태일 때만 손 버튼 → 정확한 요청 리스트/하단 비활성화 → 정확한 초기화 확인 문구/확인 → 실제 차단 아이콘 2회 재확인으로 진행한다. 이미 차단된 손 버튼은 요청을 다시 켜므로 절대로 누르지 않는다. 관측된 요청/요정, 비활성화/비할성화, 초기화/조기화 오독만 해당 문구에 한정해 처리하며, 일반 확인창/활성화 명령은 실행하지 않는다. 미확인 상태는 요청 차단 성공으로 표시하지 않는다. bootstrap/수동/런타임 모두 실제 변경 카운터를 반영하고, 재시작/재검증 시 낡은 요청 보호 증거를 폐기한다.

첨부에서 개인정보 없는 footer/요청 리스트/확인창만 회귀 fixture로 추가했다. 실제 타 계정의 요청 거절, 48시간 만료, 다중 방, 물리 모니터 OFF/잠금 검증을 대체하지 않는다. Android/backend는 변경하지 않는다. 실기 및 CI 결과는 검증 후 기록한다.
