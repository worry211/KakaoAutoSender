# 사진 기능 통합 점검 · 2.3.14 (45)

이 버전은 2.3.6~2.3.13의 사진 전달·학습·예약 UI를 한 흐름으로 정리한 시험판이다. 사용자에게 작은 변경마다 재설치와 재시험을 요구하던 방식을 멈추고, 아래 문제를 한 APK에 묶었다. 전체 목표인 여러 방 사진 자동 순회와 확실한 화면 OFF 전송이 완성됐다는 뜻은 아니다.

## 이번에 함께 수정한 부분

1. **사진 키보드가 카카오톡 입력창을 가리는 구조.** `InputMethodService.setInputView`는 반환한 루트 뷰를 MATCH_PARENT/WRAP_CONTENT로 추가하므로, 기존 루트 ScrollView에 지정한 높이가 유지되지 않았다. 내부 자식 컨테이너에 높이를 지정하도록 바꾸었다. 세로/가로 모두 화면 높이의 40%와 310dp 중 작은 값 이내에서 스크롤한다. 루트의 LayoutParams가 프레임워크에 의해 바뀌는 상황을 테스트한다.
2. **키보드가 활성 창일 때 카카오톡을 못 찾는 문제.** 접근성의 interactive windows 조회를 켜고, 포커스/활성 상태가 확인되는 카카오톡 앱 창을 선택한다. 다른 앱이 앞에 있거나 앱 창 포커스가 서로 충돌하는 경우에는 뒤의 카카오톡 창을 선택하지 않는다. 이름이나 좌표로 방을 추측하지 않는다.
3. **긴 대화 목록 때문에 방 확인이 실패하는 문제.** 방 제목과 메시지 입력창을 찾을 때는 대화 목록 하위 노드를 건너뛴다. 대화 내용을 읽거나 저장하지 않으며, 제목·입력창의 유일성과 창 ID/제목 해시 검사는 유지한다. 사진 미리보기의 구조 검사는 계속 전체 제한을 적용하며, 너무 큰 구조는 추측하지 않는다.
4. **현재 실패와 과거 준비 완료가 동시에 보이는 문제.** `PhotoUiReadiness`가 현재 연결·편집창·워크플로 단계를 기준으로 학습/예약 가능 여부와 현재 안내를 함께 결정한다. 학습 이력만 있고 현재 방을 확인하지 못하면 예약을 노출하지 않는다. 이전 처리 기록과 최근 예약 기록은 설정의 접힌 고급 정보로 분리한다. 연결 상태가 바뀌면 낡은 조작 오류를 지운다.
5. **학습 버튼이 계속 비활성화되거나 확인 체크가 사라지는 문제.** 준비 전 IDLE 상태에서도 창 변경을 받아 현재 연결이 회복되면 버튼이 다시 활성화된다. UI 갱신 시 확인 체크와 고급 옵션을 유지하고, 새 사진/입력창이나 명시적 취소에는 확인을 해제한다. 사진 선택 유효 시간은 30초에서 2분으로 늘리고, 만료를 명시한다.
6. **중복된 버튼과 긴 설정 화면.** 사진 선택 후에는 수동 전달·전송 준비를 표시하고, 현재 방의 준비가 끝나면 10초 1회 시험·일정 1회·반복을 표시한다. 준비 중에는 취소만 제공한다. 고급 옵션과 과거 기록은 접힌 상태로 시작한다. 현재 방 확인 및 저장 사진 검사는 각 전송/예약 실행에서도 다시 수행한다.
7. **예약의 옵션 및 실패 처리.** 고급 화면 꺼짐 실험 선택이 10초 1회 시험에도 전달되도록 수정했다. 기본은 화면 켜짐이다. 저장 오류는 시작 실패로 처리하고, 중복 재전송·연속 만회 전송을 추가하지 않았다. 기존 시도 한도·실행 ID·라이선스·최종 버튼/복귀·입력 연결 검사와 중지 경로를 유지한다.

## 현재 흐름

방 설정의 사진을 선택 → 카카오톡의 실제 받는 방에서 사진 키보드 열기 → 사진과 현재 방 확인 → 전송 준비 1회 → 카카오톡에서 마지막 전송 버튼을 직접 누름 → 원래 방에서 준비 상태 확인 → 10초 시험 또는 예약·반복.

준비 과정은 실제 사진 한 장을 보낸다. 다른 사진을 골라도 수신자를 자동 선택하지 않는다. 학습·키보드 입력 수락·버튼 누름·방 복귀는 상대 수신 완료를 뜻하지 않는다. 카카오톡 재실행·다른 방 이동·업데이트·재부팅 뒤에 이전 입력 연결이나 학습 창을 임의로 재사용하지 않는다.

## 검증과 남은 한계

- 세로/가로 키보드 높이, 키보드 창 뒤의 포커스 앱 선택, 타 앱/다중 창 거절, 700개 대화 노드 제외, 준비 전후/현재 창 미확인 시 버튼 구성, 확인 체크 유지, 늦게 나타나는 창 연결의 복구, 과거 성공 문구 배제, 명시적 화면 꺼짐 시험 옵션을 자동 테스트한다.
- 기존 미디어 공유 권한·여러 방 일괄 설정·문자 및 사진 알림 경로·사진 시도 한도·중복 알람·설정 변경·중지·잠금·라이선스 테스트를 함께 실행한다.
- 현재 연결된 휴대폰이 없어 사용자 기기의 실제 카카오톡 예약·반복·키보드 접기와 이번 통합 변경의 실제 사진 수신은 검증하지 못했다. 자동 테스트 수와 빌드 통과를 실기기 검증이라고 표시하지 않는다.
- 여러 방에 설정을 저장하는 기능은 유지하지만 **여러 방 사진 자동 순회는 미구현**이다. 같은 카카오톡 방과 입력 연결을 유지해야 하는 현재 엔진의 제약은 남아 있다.
- **실제 화면 OFF/보안 잠금 상태의 사진 반복 지원을 보장하지 않는다.** 고급 옵션은 연결과 창 접근이 유지될 때만 시도하는 실험이다. 화면을 켜거나 잠금을 풀지 않는다. 이 버전을 화면 OFF 완성 제품으로 판매하거나 자동 배포하지 않는다.

## 확인한 플랫폼 근거

- [AOSP Android 16 InputMethodService.setInputView](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/core/java/android/inputmethodservice/InputMethodService.java): 프레임워크가 입력 뷰 루트의 LayoutParams를 설정한다.
- [Android AccessibilityServiceInfo](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo#FLAG_RETRIEVE_INTERACTIVE_WINDOWS): interactive windows 조회에 필요한 서비스 설정.
- [Android InputConnection.commitContent](https://developer.android.com/reference/android/view/inputmethod/InputConnection#commitContent(android.view.inputmethod.InputContentInfo,int,android.os.Bundle)): 대상 편집기와의 협력적 콘텐츠 입력이며 수신 완료 확인 API가 아니다.
