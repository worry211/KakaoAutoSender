# Android 사진 전송 시험판

버전: 2.3.6-photo-preview (37). 일반·오픈채팅의 실제 사진 도착과 물리 화면 OFF 동작은 미검증이다. 이 문서는 상용 지원 보장이 아니다.

## 구현 범위

- 기존 문자 답장 선택과 일정 저장 형식을 유지한다.
- 같은 알림 답장 액션의 텍스트 입력과 `getDataOnlyRemoteInputs()`를 함께 수집한다.
- 일반 알림과 WearableExtender에 별도의 사진 답장 액션이 있으면 해당 액션의 입력과 PendingIntent를 함께 보관한다. 문자 액션에 다른 사진 액션의 입력을 섞지 않는다.
- 이미지 전용 답장만 있는 알림도 연결 대상으로 수집하되 문자 전송은 차단한다.
- 사진 MIME 및 문구를 함께 받는 액션이 있을 때에만 기존 스케줄러로 전송을 요청한다. 액션이 없다면 사진을 문자로 바꾸거나 요청 성공을 꾸며내지 않는다.
- 카카오톡 액션이 잠금 해제를 요구하면 잠긴 상태에서 전송하지 않는다.
- 새 ‘카카오톡에서 사진 직접 보내기’는 선택한 사진을 카카오톡 공유 화면으로 전달한다. 사용자가 방 선택과 최종 전송을 직접 한다. 자동 반복·화면 OFF 기능이 아니며 문구는 포함하지 않는다. 앱은 화면을 열었다는 이유로 전송 횟수를 올리거나 성공 로그를 남기지 않는다.
- 방 화면에 사진 입력 감지 여부를 표시한다. 감지는 실제 사진 수신 확인을 뜻하지 않는다.

## 추가하지 않은 것

수정 카카오톡, LSPatch/Xposed 모듈, 카카오톡 내부 통신 클라이언트, 접근성 좌표 조작은 이 시험판에 포함하지 않았다. 조사에서 확인한 Kleek의 사진 빌더는 루트 설정 읽기와 버전별 내부 클래스 매핑에 의존해 일반 APK에 그대로 붙일 수 없다. 카카오톡이 사진 입력을 제공하지 않는 기기에서는 알림 사진 자동전송이 여전히 차단된다.

## 실기기 검증

사용자가 지정한 시험 방과 사진만 사용한다. 일반 채팅과 오픈채팅을 각각 확인한다.

1. 기존 서명으로 기존 앱 위에 설치해 라이선스·등록 방·문구·일정·사진 선택이 유지되는지 확인한다. 앱 데이터 삭제나 카카오톡 교체를 요구하지 않는다.
2. 새 알림을 받고 방을 검증한 뒤 사진 입력 감지 여부를 확인한다. 입력이 없으면 자동전송이 차단되어야 한다.
3. 입력이 있으면 1회 요청 후 수신 기기에서 실제 사진과 문구를 확인한다. PendingIntent 수락만으로 도착 성공을 판정하지 않는다.
4. 실제 디스플레이 OFF, 보안 잠금, 장시간 대기, 알림 제거·교체, 전체 중지, 라이선스 정지를 각각 시험한다. 실패 시 문자 대체 전송이나 다른 방 전송이 없어야 한다.
5. 직접 보내기는 카카오톡에서 수신 방을 확인하고 보낸다. 취소·앱 복귀 시 자동 성공 기록이나 재시도가 없어야 한다.
6. 기존 문자 전송과 여러 방 예약이 유지되는지 확인한다.

실기기 검증 전에는 고객용 자동 업데이트나 판매 지원표에 오픈채팅 사진·화면 OFF 지원을 추가하지 않는다.
