# 사진 자동전송 흐름 시험판 2.3.12 (43)

목표는 여러 방에 같은 사진·문구·일정을 한 번에 적용하고, 채팅창 유지 없이 화면이 꺼져도 전송하는 것이다. 이 버전은 그 목표의 완성본이 아니다.

## 구현한 변경

- 사진 전송 버튼 학습과 원래 채팅방 복귀가 끝나면, 같은 프로세스의 사진 키보드에 준비한 사진과 저장 일정이 표시된다. 사진을 다시 선택할 필요가 없다. 사진 변경·삭제나 다른 방으로 이동하면 이전 준비 상태를 그대로 사용하지 않는다.
- 현재 방 확인 후 `10초 후 자동전송 1회 시험`으로 실제 자동 최종 클릭과 복귀를 시험할 수 있다. 저장한 반복 일정은 바꾸지 않는다. 이 시험도 사진 한 장을 실제 전송하며 기존 라이선스·무결성·학습·수신자 확인·하루 한도·중복 방지 검사를 적용한다. 정확한 알람 권한이나 절전 상태에 따라 늦어질 수 있다.
- 같은 준비 화면에서 저장한 일정의 반복 전송을 시작할 수 있다.
- 예약 중 `키보드 접기 · 예약 유지`를 제공한다. 키보드 뷰가 닫혔다는 사실만으로 취소하지 않고, 동일한 카카오톡 창과 입력 연결·설정·라이선스가 유효할 때만 유지한다. 입력 연결 종료, 다른 앱이나 방 이동, 다른 키보드 선택은 계속 중지 사유다. 키보드를 접은 상태의 실제 기기 동작은 아직 미검증이다.

## 구현/검증 상태

| 항목 | 상태 |
|---|---|
| 여러 방에 사진·문구·일정 일괄 설정 | 기존 구현 유지 |
| 오픈채팅 사진 수동 전달 및 최종 전송 | 사용자 실제 수신 보고 |
| 전송 버튼 학습 및 원래 채팅방 복귀 감지 | 사용자 2.3.11 화면으로 확인 |
| 사진 재선택 없이 시험/반복 시작 | 이번 구현, 자동 테스트 및 빌드 검증 |
| 실제 사진 자동 최종 클릭·반복 | 사용자 기기 수신 검증 필요 |
| 키보드 접기 후 예약 유지 | 이번 구현, 사용자 기기 검증 필요 |
| 다른 앱 사용 중/여러 방 자동 순회 | 미구현 |
| 실제 디스플레이 OFF에서 일반·오픈채팅 사진 반복 | 지원 근거 및 실기기 검증 미확보 |
| 보안 잠금 해제나 화면 제한 우회 | 구현하지 않음 |

## 남아 있는 구조적 문제

현재 전송기는 일반 앱의 독립적인 사진 전송 API가 아니라 현재 카카오톡 편집기의 `InputConnection.commitContent`를 사용한다. Android가 연결을 종료하거나 카카오톡 창을 접근성으로 확인할 수 없으면 진행할 수 없다. 키보드 패널을 접는 것과 실제 화면 OFF/앱 전환은 별개다. 여러 방 설정을 저장하는 것과 여러 방을 자동으로 찾아 보내는 것도 별개다.

화면 OFF·다중 방 엔진을 완성하려면 기존 입력 연결에 의존하지 않는 전송 경로와 확실한 수신자 식별이 필요하다. 현재 사용자 기기에서는 알림의 사진 RemoteInput이 없으며, 공개 공식 API만으로 일반/오픈채팅 임의 방의 사진을 전송하는 경로를 확보하지 못했다. 창 이름만으로 대상을 추측하거나 이전 입력 연결을 임의 방에 재사용하지 않는다. 코드 테스트 통과를 실기기 전송 완료로 취급하지 않는다.

Android 공식 입력 연결 계약:
https://developer.android.com/reference/android/view/inputmethod/InputConnection#commitContent(android.view.inputmethod.InputContentInfo,int,android.os.Bundle)

이번 세션의 ADB 조회에 연결된 휴대폰이 없었으므로 실제 카카오톡 예약이나 사진 전송을 실행하지 않았다. 자동 테스트는 빠른 1회 시험의 시간·일정 불변·단발 종료·학습/수신자 확인·하루 한도와 기존 중복 방지/입력 연결 검사를 포함한다. 실제 기기에서 먼저 자동 1회 전송과 복귀를 검증해야 하며, 판매 설명에서 화면 OFF·여러 방 사진 반복 지원을 확정하지 않는다.
